# Testing

## Automated (no customer data; synthetic fixtures only)

| Layer | Command | Covers |
|-------|---------|--------|
| UI logic | `node test_ui_regression.js` | Job summary, labor, quote, elimination status, preparation holds |
| Static | `go vet ./...` | |
| Go suite | `go test -count=1 -timeout=20m ./...` | PDF extraction, schematic/wire tracing, cavity model, connector audit, labor, repository hygiene (`repo_hygiene_test.go`) |
| Stability | `go test -shuffle=on -count=5 -timeout=20m ./...` | Order dependence; run for parser, lifecycle or UI-state changes |
| Executable | `node scripts/smoke.js <exe>` | Token protection, 127.0.0.1 binding, synthetic PDFs, self-test, shutdown (headless via `TRIVEX_NO_WINDOW=1`) |

Fixtures live in `testdata/` and are generated by `synth_fixtures.go` and `scripts/create_synthetic_acceptance_pdfs.py`. Never add customer drawings, screenshots or extracted content.

Everything above runs on Linux (`go test`, a Linux build for the smoke test) and on Windows via `.github/workflows/windows-build.yml`. A green build is not acceptance.

## One command on the owner's PC

`powershell -ExecutionPolicy Bypass -File .\run_local.ps1` runs the full gate (`build_windows.ps1`), then starts the built executable. `-SkipChecks` just rebuilds and starts. `-Shuffle` adds the shuffled Go run.

## Owner-controlled acceptance (not automatable remotely)

1. Run `run_local.ps1`; confirm the Edge window opens, shows a drawing, and the process exits when the window closes.
2. Load a real drawing locally. Compare the five answers in the Job summary with the shop's own counts. Local scoring: set `TRIVEX_SCORE_DIR` and run `go test -run LocalScore -v` (prints numbers only).
3. Work through `QA_CHECKLIST.md`.
4. Confirm no network traffic leaves the machine while a drawing is processed.
5. Record results in `CURRENT_STATE.md`.
